# 游戏客户端工程师系统课程 · 总蓝图（V2.3）

> **文件定位：** 这是供学习网站、课程内容生成器与 AI 导师共同遵守的「课程规划单一事实源」（SSOT），**不是**已写完的教材，也**不是**真实的学习成绩。网站应读取/导入本文的课程目录；具体课文、练习题、学习记录另行存储。
> **长期目标：** 从「学过计算机概念、编程能力按入门起步」发展为能独立通过游戏客户端实习笔试和技术面试，具备原理解释、从零编码、错误定位、边界处理、技术取舍、可扩展设计与需求迁移能力。

## 0. 如何使用这份蓝图（先读本章）

### 0.1 文件的角色：一份规划，三类独立数据

这份 Markdown 是**课程总规划与网站生成规则的单一事实源（SSOT）**，不是一次性生成的教材，也不直接保存个人答题数据。请分清：

| 内容 | 谁负责 | 存放位置建议 | 能否被更新覆盖 |
|---|---|---|---|
| **课程规划**：学科、课次 ID、目标、知识边界 | 本蓝图 | `curriculum/curriculum-plan.md` | 允许版本化变更，保留 ID/迁移记录 |
| **实际教材与练习**：每节课的图文、动画、A/B/C 题、测试 | 逐课生成的课程文件 | `content/<COURSE>/<LESSON>.md` 与 `exercises/` | 允许修订，但保留题目版本和历史映射 |
| **学习档案**：首次答案、最终答案、代码、错误、导师反馈 | 网站保存 + 用户主动提交/导入 | 浏览器本地/用户私有数据库及备份文件 | **不可被教材更新覆盖** |

课程表是**目标路线**，不等于已制作课程；已阅读或点过答案，不等于独立掌握。

### 0.2 第一次使用：建站与导入（只需做一次）

1. 创建一个网站项目目录 `gamedev-academy/`，把**最新版本**总蓝图复制为 `curriculum/curriculum-plan.md`；V2.1 等旧版单独归档，不作为网站的当前读取入口。
2. 按第 6 节的目录和数据契约建立课程索引、教材读取、练习保存、复习中心和报告导出功能。**网站初始只需 C++ 前两课**，不要先生成全部 125 个单元。
3. 先产出 `CPP-01.md` 和对应 A/B/C 练习配置，题目 ID 与课程 ID 一致且固定；`CPP-02` 可在首版中用于验证新课追加机制。
4. 实现课程页的 A 题即时判定、B 题编辑与**真实可验证的**运行/测试能力（暂不能执行则明确写“需外部验证”）、C 题文本/代码保存。
5. 实现「错题本 + 需求变更复习 + 课终学习回执导出/导入」，实际测试**刷新页面、关闭再打开、导出备份、恢复数据**能否保留答案和学习进度。
6. 验收后才让课程开始正式计分；演示数据不得伪装成个人真实成绩。

若当前只是想开始学习，也可以**不等网站完成**：直接依据第 7 节在 ChatGPT 生成一整课，完成训练后再把内容迁入网站。

### 0.3 平时怎么学一课（学生端 SOP）

1. 网站首页查看「当前主线课程」「继续学习」「今日到期复习」；只推进当前一门主课。
2. 进入一课，完整阅读知识导入、原理演示、真实游戏案例、方案对比和边界分析。理解后再做题，不以阅读时长判定掌握。
3. **A 类题**：在网页上直接选择/判断/预测输出，**即时**显示对错和解释，不向 ChatGPT 逐题发送消息；保存首次作答与后续纠错记录。
4. **B 类题**：在网页代码编辑区亲自输入、修改、运行可用测试，保留代码、尝试次数、编译错误及测试记录；如果网站暂时没有适配编译器，使用正规在线判题平台或本地编译器，并把证据记录回页面。**不能把静态模拟当作真实通过。**
5. **C 类题**：独立写原理解释、技术选型、边界测试和需求变化后的方案/代码；答案先保存在网页，不逐题发送给导师，不得提前显示完整参考解法。
6. 学到一半有不懂的：按需打开学习对话，连同 `lesson_id`、当前知识点、疑问、代码/错误一起提问；答疑后返回**同一课**继续，不另起主线。
7. 本课练习结束，点击「生成学习回执」，导出 Markdown/JSON（见第 6.3 节），**一次性**上传/粘贴给 ChatGPT；不能只说“我做完了”。
8. 阅读导师对证据的批改，修订代码或补练薄弱点，把反馈保存/导入网站；达标再进入下一课，未达标则只针对问题补练，保留主线与全部历史。
9. 课后在网站复习中心处理到期错题和需求变化题（见第 4 节）。**不强制停下主线等所有复习清零。**

### 0.4 如何请 AI 生成或更新下一课（课程维护 SOP）

1. 先提供/授予 AI 当前 `curriculum-plan.md`、当前课程已有课文/题目（如果有）、上一课的学习回执或导师反馈，以及明确的目标 `lesson_id`。
2. AI **先核对**第 3 节中的课程主题、先修条件、贯穿案例、知识目标；根据回执调整难度，但**不能擅自跳过主线或修改课程 ID**。
3. 每次只生成/更新**一节**课程的 `content/...md` 与练习配置；需要的图示、互动、编程题和测试与课次一起生成，避免出现“有教材无练习”。
4. 对照第 2 节和第 7 节逐项自检：**原理、游戏应用、技术取舍、边界、性能、扩展、验证、迁移**；A 题即时判、B 题可测试、C 题可导出；至少一个需求变更挑战和复习知识标签。
5. 构建/预览网站，验证新课显示、导航、保存、代码测试和报告导出；确认不会清空旧课程的学习数据后再发布。
6. 修正题目时增加 `content_version`/`question_version`，不得改写旧尝试、旧分数。若大规模调整课程顺序、增删课，先更新本蓝图及映射，再改网站。

**可直接复制的「生成下一课」指令：**

> 请以 `curriculum/curriculum-plan.md`（V2.2 或更新版本）为唯一课程规划依据，读取现有教材、练习与上一课学习反馈。为【课程 ID：CPP】【课次 ID：CPP-01】生成/修订**一整节**适合独立编程入门者的课程，包括原理、游戏案例、取舍、边界、性能、扩展、验证、迁移；输出可渲染的 Markdown 课文、A 类即时题 2–4 道、B 类独立代码题 1 道及测试配置、C 类深度思考/设计题 1 道、需求变更题、知识标签和错题复习配置。沿用稳定 ID，不覆盖用户记录。完成后说明修改了哪些文件、如何验证以及哪些测试尚未运行。若存在已经写好的课，只修订被要求的部分。

### 0.5 每课完成后，如何交给 ChatGPT 批改与更新总控

- **你操作：** 在网站点击「导出本课学习回执」，把文件上传到学习主线对话（或粘贴全文）；如果有本地 Unity/编译器结果，把关键日志、测试输出或项目证据一并附上。
- **我负责：** 先分清网站自动判题与真人可验证的实测证据，再评估 P/I/B/T/E/V 六维能力，给出已掌握项、错误根因、需求变更追问、建议补练题及下一课是否可以继续；**没评估的维度填 `null`**。
- **回到网站：** 通过「导入导师反馈」或人工确认将评分、错题标签、复习日期、迁移挑战和主线课次更新到学习档案。若暂不做反馈导入功能，先保存导师回复为独立 Markdown，避免统计丢失。
- **本总控对话：** 可定期汇总已经上传的学习回执和真实成绩，分析跨课程薄弱点；**不能假设我能直接看见你的浏览器本地数据库，也不能在后台持续监控网站。**

**可直接复制的「批改一课」指令：**

> 这是【课程 ID】【课次 ID】的学习回执，请基于我实际写的答案、代码、编译/运行日志与错题记录进行一次集中批改。区分客观判题和需要人工审查的能力，给出 P/I/B/T/E/V（每项 0–4，证据不足用 `null`）、边界/性能/选型/扩展问题、最小必要补练、错题复习与需求变更任务，并明确能否进入下一课。请输出可保存到网站的简短导师反馈摘要；不要直接覆盖旧作答记录。

### 0.6 网站更新、数据安全与故障处理

- **每次新建/改版网站：** 先备份 `curriculum/`、`content/`、`exercises/`，再确认用户学习数据的存储方式；升级前导出一次完整个人学习档案。
- **本地存储模式：** IndexedDB/localStorage 只能被同一个站点来源对应的浏览器配置访问；换设备、清浏览器数据、改变网址/域名都可能失去记录。保持**导出与导入**可用，不将学习数据只存在内存中。
- **公开仓库与隐私：** 不把个人答案、学习报告、访问令牌或在线判题凭据提交到公开 Git 仓库；Git 中主要保存蓝图、公开教材与练习定义。
- **无法自动编译时：** B 题标注 `unverified`，引导使用外部 C++/C# 运行环境，记录所用编译器/版本、测试用例与输出，再由导师结合证据判断。不要假造全通过。
- **新课上线后旧错题找不到：** 先查课程/题目稳定 ID、旧版本快照与迁移映射，不删除历史；恢复问题题目/解析对应关系后再继续复习。
- **课程计划与实际不一致：** 以本文件最新生效版本确定未来教学安排，以带版本的真实学习日志确定**过去学了什么**；任何迁移都可追溯。

### 0.7 一句话协作分工

**这份蓝图定路线 → 网站负责阅读、A/B 练习、学习数据和复习 → 用户独立完成 C 题 → ChatGPT 课末深度批改并指导下一课 → 网站导入反馈、保留历史。** 网站是持续学习的工具，**不能让建站工作代替真正学编程**。

### 0.8 文档版本约定

- **修改课程：** 先提高此文档版本号，再更新网站内容；不直接修改既有学习日志。
- **编号永久稳定：** `CPP-01` 等 ID 不因修改标题而改变；新增课用新 ID，不复用被废弃的 ID；结构变动时维护迁移映射。
- **当前状态：** 下面专项课程均为规划，不意味着网页或教材已经制作，亦不代表已掌握。之前计算机基础系列尚有最后一课待补，不计入本次 125 个单元。

### 单门顺序学习主线

`C++ → 数据结构与算法 → C# → Unity → 操作系统 → 网络同步 → 数学与图形学 → 架构 → 性能 → 工程工具`

- **原则：** 同一时段只推进一门主课，一次产出一整课。进入下一门前完成阶段评估；不需要机械地把全部课程学完才去投实习。
- **面试训练：** `INTERVIEW-01` 入学诊断放在最开始；其他面试单元随对应知识成熟穿插或在各门结课时执行，**不要求**集中到最后才做。
- **进度兼容：** 若之后按笔试日期需要优先刷某类算法或 Unity 高频题，可以临时插入专项复习，主线位置保留。
- **门槛：** CPP 前四课能基本独立编译、写函数、看懂引用和指针后，算法课才能高效推进；C# 的事件和集合基础到位后，再深入 Unity 架构；性能课应建立在 Profiler 与引擎流程实践基础上。

## 2. 统一教学方式（课程生成不可省略）

### 2.1 一课一完整输出，而不是一题一对话

每次生成 **一整课**，内容顺序：`学习目标/先修 → 游戏问题引入 → 知识关系图与分步原理 → 代码/实验演示 → 与替代方案比较 → 典型边界与错误 → 课内 A/B/C 练习 → 需求变化挑战 → 本课知识图谱与复习钩子`。

用户可在网站完成所有 A 题、B 题和 C 题，再生成**一份**课程学习报告，供 AI 导师集中批改。用户学习过程中确有不懂时可以单独问答，但并非必经步骤。讲解需从编程零基础可理解的例子起步，实际掌握以测验/代码为准；已学过概念 ≠ 已达到工程能力。

### 2.2 每个核心知识点必须回答八维问题

| 维度 | 核心追问 |
|---|---|
| 原理 | 底层过程是什么、为什么成立；是语言保证还是实现细节？ |
| 游戏应用 | 在游戏中解决什么真实问题，何时不需要？ |
| 技术选择 | 相似方案有哪些，为什么选这个，不选别的会怎样？ |
| 边界异常 | 空值/越界/销毁/极端规模/输入错误/并发失败时如何？ |
| 性能成本 | 时间/空间/分配/GC/CPU/GPU/网络成本及测量依据？ |
| 扩展维护 | 需求增长、团队协作或版本升级时怎样演化？ |
| 验证调试 | 怎样构造测试、观察日志、复现缺陷并验证修复？ |
| 迁移变通 | 限制改变后原方案是否仍成立，何时需要更换设计？ |

### 2.3 交互/练习分层：减少消息

| 类型 | 示例 | 在网站里的反馈 | 是否每题发给 AI |
|---|---|---|---|
| **A 即时理解** | 选择、判断、代码输出预测、拖拽流程 | 本地即时判定 + 完整解析 + 反例；保存首次答案 | **否** |
| **B 自动验证** | 函数填空、代码修改、算法小题、Unity 本地实验记录 | 执行真实测试（可用时）+ 输出差异 + 测试覆盖；仅模拟时必须明示 | **否** |
| **C 深度评估** | 独立实现、设计说明、边界测试、技术比较、需求变更 | 保存完整正文/代码/实验材料，课末汇总 | **每课集中一次** |

- 默认每课 **A 2–4 个 + B 1 个 + C 1 个**；涉及纯设计/Unity 编辑器的课允许用实验和结构图替代编译题，但必须有实际可验证证据。
- 每课至少一项「**约束变化挑战**」：可能是数据规模、对象生命周期、低端设备、断网、多人同步、跨场景存档、团队维护等。不能靠背原例题直接过关。
- 任何自动判题结果必须区分「编译通过」「公开测试通过」「边界测试通过」「人工审核通过」。运行成功一次 ≠ 逻辑正确。
- **不要先泄露 C 题完整标准答案**；先提示思路，再分级提供伪代码/关键节点，用户提交后再批改。

### 2.4 真实代码执行约束

- C++：教学示例以 **C++17** 为基线，C++20 新特性单独标注；通过可用的沙箱/编译服务运行、测试，不应宣称未执行的代码“已通过”。
- C#：区分纯 .NET 控制台代码与 Unity 环境代码，并标注运行时要求。
- Unity：GameObject、MonoBehaviour、Profiler、引擎 API 相关实践必须能在本地 Unity Editor/项目中复现；网站只能展示指导、部分模拟或接收结果，不能以模拟运行冒充引擎实际执行。
- 暂不自建不受限的任意代码执行后端；若集成判题服务，必须考虑沙箱隔离、执行时长、内存限额、网络访问和滥用风险。

## 3. 各门课程详细课次与实战规划

### `CPP` · C++ 语言与内存模型（12课/单元）

## 4. 错题回顾与需求变更复习（首版必须实现）

### 4.1 错题不是只保存“答错了”

记录 `question_id`、`lesson_id`、知识点标签、题目/课程版本、首次答案（包括代码）、实际输出/测试结果、错误类型（概念/语法/逻辑/边界/复杂度/设计/粗心）、正确解释、补做尝试次数、最后一次通过证据与下一次复习日期。

### 4.2 复习分两条线

1. **理解纠错：** 自己重新解释原理，做同知识点不同题面的小题；避免只记答案位置。
2. **需求变更迁移：** 在原题上增加新的约束，要求写出“原方案继续使用/修改/替换”的判断、代价与必要测试；若只是复述教材，不算迁移通过。

复习初始建议为 **当天纠错 → 第1天同类变式 → 第3天迁移 → 第7天需求变化 → 第14天综合**；如答错或不能解释，动态调回较近的复习阶段，不强制按日期机械解锁。可在后续加入第30天回顾。

**示例（C++ 容器）：** “10个道具的背包，按顺序显示”用 `vector` 可以合理 → 新需求“10万个道具、频繁按ID查找、同时排序、还要持久化”时，需要区分「主数据列表」和「查找索引」，比较 `vector`、`unordered_map`、`map` 的时间/空间/迭代稳定性及一致性维护，给出测试。

### 4.3 知识点掌握状态

`未学 → 已讲解 → 已练习 → 待复习 → 已验证掌握 → 已迁移通过`；若同一知识点复习失误，可从“已验证掌握”回退为“待复习”，但历史成绩/提交不可删除。

## 5. 能力评估与进度统计

| 维度 | 代码 | 评分基准 |
|---|---|---|
| 原理 | P | 能解释机制、条件及例外 |
| 独立实现 | I | 未依赖直接答案完成可运行实现或严谨实验 |
| 边界异常 | B | 能主动设计并处理失败和极端条件 |
| 技术取舍 | T | 比较替代方案，说明选择依据 |
| 扩展维护 | E | 对新需求做合理改造并评估影响 |
| 验证调试 | V | 有测试/输出/复现/日志等验证证据 |

- 每维 **0–4 分**；未考核时填 `null/未评估` 而不是 0。课程正式考核时 6 维都须有证据；每维≥3 且总分≥20/24 才可标为「已验证掌握」。
- **三种进度彼此分开：** `内容学习进度`（读了几课）、`完成练习进度`（做了多少题）、`能力验证进度`（哪些课有证据通过）。
- 评分必须基于真实答案、代码、运行/测试结果；不能把演示题、复制参考答案或仅口头表示理解计为独立通过。
- 每 3–4 课安排一次跨知识点复习；每门课结束至少一次独立实现/综合题与答辩。面试单元可读取这些真实证据。

## 附录 V2.3：面试八股审校与在线增量更新规范

1. **课程主线保持11模块125单元不变。**《八股.docx》《八股-2.docx》只提供高频面试问题与场景约束，不能直接作为权威答案导入。新增题目应先核对概念、编译器或Unity版本，标记 `verified` / `needs-review`。
2. **新增题库模块：** `src/data/interview-bank.js`，每条记录带稳定 `id`、`source`、`sourceTopic`、`lessonId`、`tags`、`status`、`question`、`change`。进阶题必须按对应 `lessonId` 的教材就绪条件解锁，不能在C++第1课就考虚表布局等高级题。
3. **题库不自动评价主观设计答案。** 用户草稿和提交记录保存于 `gda-v1-learning-archive` 的 `interview` 字段，课末或独立导出回执给导师。所有资料来源标记仅用于追溯。
4. **课程更新策略：** 代码放 GitHub 仓库；建议 GitHub Pages 部署静态资源。新增教材修改 `src/data/lessons/<id>.js`，并运行 `python scripts/build_offline.py`。课程和练习版本更新但不要修改原有ID。
5. **学习档案与站点代码分离：** GitHub 只存课程内容与代码，浏览器保存学习档案。GitHub Pages不会自动将 `localStorage` 同步到其他设备；定期导出JSON备份。不要提交个人学习报告、API Key、判题器令牌或原版私人资料到公共仓库。
6. **在线与本地使用：** 网站在线部署可直接阅读、即时作答、保留浏览器数据；真实C++编译仍需独立沙箱或在线编译器，不能把文本静态检查当做编译测试。
7. **以后让AI更新：** 指定仓库和课次ID；先读取本文及已上线课内容，再只修改本次课次和关联的题库数据、版本记录，测试后提交Git；不用反复传整个ZIP。
